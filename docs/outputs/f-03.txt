# - FACTS CHECKED (Workers Rate Limiting docs, last updated 2026-10-21, read 2026-11-03 maxAge 0): period must be 10 or
#   60; limits are approximate and per Cloudflare location (requests can exceed them while counts sync); keys should be
#   a user or API key, NOT an IP (many users share one); for a strict limit use a Durable Object. That's the lesson's
#   split: the binding stops bursts, the Durable Object (each Klippy's SQLite) holds the exact daily budget.
# - Limits stack, outermost first: web USER_LIMITER (30/min per GitHub id) -> agent LIMITER per Klippy (chat 10/min,
#   search 10/min, file 10/min; since c-03/e-02/e-05) -> the daily token budget -> maxOutputTokens 300 and 8 steps a turn.
#   The public /klippy/check stays limited by address (no user to key on) plus its shared probe key and cache.
# - The budget is checked before a turn and charged after it, so the last turn of the day can overshoot by one turn
#   (at most 8 steps x (prompt + 300 output tokens)). Say so; it's the price of not guessing a turn's size up front.
# - What's not counted: /ask and /note (token-only routes, no web path to them) and the ingest context step (capped at
#   30 sources a day per Klippy, e-02). Gateway spend limits (f-02) are the account-wide backstop in dollars.
