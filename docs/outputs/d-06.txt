READMEs first.
Constraints:

- Only my GitHub account id may sign in (ALLOWED_GITHUB_IDS, not logins: those can be renamed); anyone else
  gets a 403 page and no session.

Plan first, then wait for my go-ahead.
Done when typecheck and remix doctor pass, and curl shows: / redirects to /login, /auth/github redirects to GitHub,
and a cross-site POST /logout gets 403. Report the files and the outputs.

## Review checklist
- [ ] The cookie is httpOnly, Secure, SameSite=Lax and signed (secrets: [env.SESSION_SECRET]).
- [ ] completeAuth() before writing the user (new session id); logout is a POST and destroys the session.
- [ ] The agent name comes from the session (gh-<id>), never from a URL or form field.
- [ ] KLIPPY_TOKEN appears only in app/agent.ts (server) — `grep -r KLIPPY_TOKEN apps/web/app`.
- [ ] The allowlist compares numeric ids, not logins.
- [ ] Scopes are read:user only. No real secret in any committed file (`git diff | grep -i secret`).
- [ ] Reject: a hand-written OAuth exchange with fetch, a session stored in localStorage, the allowlist checked only
      at sign-in (it must be re-checked per request), `?token=` in a browser URL.

## Steer prompts
- "You wrote the GitHub token exchange by hand with fetch. Delete it and use createGitHubAuthProvider with
  startExternalAuth / finishExternalAuth from remix/auth, as the README shows."
- "context.auth.identity doesn't typecheck in home. Move requireUser from the action to the controller's
  middleware, so the controller's context knows the user is signed in."
- "Anyone with a GitHub account can sign in. Add ALLOWED_GITHUB_IDS, check the profile id in the callback (403, no
  session) and the stored id again in the auth scheme's verify()."
- "You compared logins. A login can be renamed and re-registered by someone else: compare the numeric id instead."
