# b-05 Klippy keeps notes. Recorded 2026-11-03 on Linux, Node v24.22.2, wrangler 4.157.0, agents 0.33.0, ai 7.0.162, zod 4.6.7, remix 3.1.0 (remix/data-table).
# MODEL: no Anthropic key on the gateway, so the Workers AI fallback (@cf/zai-org/glm-4.7-flash) answered.
# Notes for the writer:
# - New here: packages/db (the `notes` table() + migrations/0001_notes.sql), the D1 binding DB in wrangler.jsonc
#   (database klippy-db, migrations_dir ../../packages/db/migrations), src/tools/notes.ts (saveNote, listNotes),
#   and test/notes.spec.ts (a real local D1, built by the migrations; the model is still fake).
# - The D1 driver: "the driver is included in the repo" (packages/data-table-d1, added in its own commit before
#   this tag). One line in the lesson, plus what it does: remix/data-table has no D1 driver of its own. Don't paste it.
#   apps/agent depends on it with "data-table-d1": "workspace:*". Its imports end in .ts, so apps/agent/tsconfig.json
#   gained "allowImportingTsExtensions": true (one line to explain).
# - The learner creates their own database: `pnpm wrangler d1 create klippy-db` (in apps/agent), then pastes the
#   database_id it prints into wrangler.jsonc. Our id is the owner's; a learner's will differ.
# - Then `pnpm wrangler d1 migrations apply klippy-db --local` before `pnpm dev`. --remote waits for b-09 (deploy).
# - Tools that need env are made per request: noteTools(env.DB). ask() takes the tools; /klippy/check passes {}
#   so the public probe can never write a note (a test checks the probe sends no tools).
# - Limits: a note is 1..1,000 characters (zod .trim().min(1).max(1000)); listNotes returns at most 20, newest first.
#   A too-long note is refused before anything is written, and the model sees the validation error (a test).
#   /ask still needs the token and the rate limit, so writes are capped at 10 a minute.
# - Two stores, said out loud later (C3/C5): D1 holds data other parts read (notes); the agent's own SQLite holds
#   one person's conversation and memory.
