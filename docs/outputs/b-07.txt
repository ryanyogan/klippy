# b-07 Strict inputs, honest failures. Recorded 2026-11-03 on Linux, Node v24.22.2, wrangler 4.157.0, agents 0.33.0, ai 7.0.162, zod 4.6.7, remix 3.1.0.
# MODEL: no Anthropic key on the gateway, so the Workers AI fallback (@cf/zai-org/glm-4.7-flash) answered.
# Notes for the writer:
# - New here: getTime's timeZone has a zod .refine() (a real IANA zone, checked with Intl.DateTimeFormat);
#   getWeather throws when Open-Meteo answers with an HTTP error; the step log gains "toolErrors".
#   test/failures.spec.ts covers a bad time zone and a 502 from the weather service.
# - Two kinds of failure, both become an error RESULT that goes back to Claude (AI SDK "tool-error" parts, which reach
#   Claude as an is_error tool_result), and the loop carries on so Claude can say what went wrong:
#     1. bad input: the schema or a refinement rejects it before execute runs (AI_InvalidToolInputError);
#     2. a failed call: execute throws (here: the weather service is down).
#   A refinement is invisible to Claude: JSON Schema can't say "a real time zone", so Claude sees a string and your
#   code checks the meaning. The error message is written for Claude ("Use a name like Europe/Berlin").
# - STRICT, honestly: the AI SDK has `strict: true` per tool, and Claude supports strict tool use on all models
#   (platform.claude.com strict-tool-use, checked 2026-11-03; strict schemas can't use minLength/maxLength/minimum/
#   maximum, per the structured-outputs limits). BUT agents 0.33.0's createAI drops the flag: its toolFields() in
#   agents/dist/ai-sdk-*.js sends only name, description and parameters (read 2026-11-03). So the repo doesn't set
#   strict, because a flag that does nothing would mislead. Teach strict as a concept and say why it isn't on here;
#   the refinement + error results are what Klippy relies on. Re-check when agents updates.
# - The recording: Lisbon used the tool normally; "Mars/Olympus_Mons" failed the refinement, and the model said so.
