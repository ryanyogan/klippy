# Notes for the writer:
# - Server (small): the agent gets the notes tools from b-05 (D1, shared by every Klippy name: they're the owner's
#   notes), and saveNote is wrapped as tool({ ...saveNote, needsApproval: true }). The turn pauses with the tool part in
#   state "approval-requested"; nothing is written until the answer comes back. A "no" becomes state "output-denied",
#   and the model is told (it gets a tool result saying so) and answers. /note (b-06) keeps the unwrapped saveNote.
# - Client (most of the lesson): scripts/chat.ts now
#   1. reads the history from the agent each turn (load()), instead of keeping its own copy;
#   2. after each reply, looks for a part in state "approval-requested" (isToolUIPart, getToolName from ai) and asks
#      "Allow? (y/n)";
#   3. sends { type: "cf_agent_tool_approval", toolCallId, approved, autoContinue: true } (MessageType from
#      @cloudflare/ai-chat/types) and prints the continuation: transport.expectToolContinuation(), then
#      transport.reconnectToStream(); the server announces it with STREAM_PENDING / STREAM_RESUMING, which the script
#      hands to the transport (handleStreamPending, handleStreamResuming, handleStreamResumeNone). In React,
#      useAgentChat does all of this; the terminal does it by hand, which is the point of the lesson.
#   4. passes the paused reply to readUIMessageStream({ stream, message }) so the continuation extends it. Found while
#      recording: without `message`, the continuation's tool-output chunk names a tool call the new message doesn't
#      have, the stream ends early, and the "Saved" sentence is never printed (the note IS saved).
#   chat.ts is now 77 lines: split it over steps (approval check, the y/n, the continuation).
# - The wording of the denied reply is the fallback model's ("I'm unable to save that note"); Claude would likely say
#   you declined. The list at the end shows notes from earlier recordings (same local D1, ids 1-14).
# - Tests (test/approval.spec.ts): the fake model calls saveNote; the turn pauses with no row in D1; the test answers
#   over a real WebSocket (SELF.fetch with Upgrade + ?token=) with the same frame the script sends, then checks D1.
#   Approve: row saved, part "output-available". Deny: no row, part "output-denied", and the model was called again.
