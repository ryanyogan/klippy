# - What changed (src/agent.ts only, plus test/loops.spec.ts):
#   1. stopWhen: isStepCount(8) (was 3): room for real multi-tool turns, still a hard cap per turn.
#   2. prepareStep, run before every step: if the same tool was called twice with the same input, the next step gets
#      toolChoice "none" (answer with what you have). ai 7 enforces it: a model that calls a tool anyway raises
#      AI_ToolChoiceViolationError (seen while writing the test), so the turn can't keep looping on tools.
#   3. readLink is back (b-08's tool, unchanged: exact links in the latest user message, no redirects, 8,000 chars
#      per page). Its question is now the last USER message (findLast), because after an approval (c-06) the turn
#      continues with Klippy's message last. The 2,000-character check uses the same message.
#   4. The lethal-trifecta cut, made stronger for a chat: once any readLink call is in the conversation (this.messages,
#      not just this turn's steps), activeTools is getWeather, getTime, readLink only: no listNotes, saveNote,
#      remember or forget until /clear (or until the page falls out of the 40 kept messages). In /ask (b-08) each
#      request started fresh; a chat keeps the page in its history, so a per-turn check would let the next turn act
#      on the page's orders. The live run below shows it: after reading example.com, "Now list my notes" gets no
#      notes tool.
# - Out of steps (amended 2026-11-03): if the 8-step cap stops a turn mid tool-call, the last step has no text. The
#   reply now ends with the same sentence as /ask (b-09), OUT_OF_STEPS in src/ask.ts. The agent wraps the stream in
#   createUIMessageStream: it passes every chunk through, then checks result.steps; only when there were 8 steps, the
#   last ended with "tool-calls", and it isn't waiting for an approval (c-06), it writes one text part. A turn paused
#   for your y/n stops early (fewer steps), so it never gets the sentence. Two tests (cap → sentence; normal answer →
#   nothing added). The Workers AI model doesn't hit 8 steps on its own, so the live chat below can't show it; the
#   test is the proof.
# - Page cut, enforced (amended 2026-11-03 after two security reviews). Teach it as three locks, outermost first:
#   1. A turn that starts with a page anywhere in the chat builds only getWeather, getTime and readLink
#      (chatTools(..., pageInChat)). The private tools don't exist in that turn.
#   2. Inside a turn, prepareStep stops offering them once readLink was called. It's ordered fail-closed: the page
#      rule is computed first, so the stuck-loop branch returns { toolChoice: 'none', activeTools } and can never
#      hand the private tools back.
#   3. activeTools only limits what the model is *offered*, so the private tools (listNotes, saveNote, remember,
#      forget) are wrapped by afterPage(): a per-turn flag, set the moment readLink runs (even for a refused link),
#      makes them throw "<name> can't run after reading a page." That's the lock behind the offer.
#   Limit to say out loud: two tool calls in the *same* step run side by side, so a listNotes the model asked for in
#   the same step as readLink (before it saw the page) can still run. It was chosen before the page was read.
#   Tests (4 new in loops.spec): page read + repeated call → toolChoice none and still no private tools; a turn
#   starting with a page has only the three safe tools in its tools object; after readLink runs, all four private
#   tools throw; a model forcing listNotes after readLink gets an output-error part. The fail-closed test fails on
#   the pre-amend prepareStep (1 failed | 5 passed), seen before the fix.
# - Cost framing: each step is one model call that resends the whole conversation, so 8 steps can cost ~8x one call.
